HOWEVER: restricting to `git log --no-merges HEAD` (i.e. only this branch's own
non-merge, first-party commit history, not everything reachable via `--all` across
every PR branch and squash-merge target) gives a materially different, smaller picture:
  git shortlog -sn --no-merges HEAD:
    29  T361

  Merged: Taimoor Shaukat/T361 = 41, IfBilal/8BitNinja = 12. Total = 53.
  Min share = 12/53 = 22.6% — FAILS the 35% floor.

This discrepancy exists because `--all` counts commits made on now-superseded/rebased
branches and both sides of squash-merged PRs (GitHub squash-merge can attribute the
squashed commit differently from the branch's original individual commits), while
`--no-merges HEAD` counts only what's actually reachable, non-merge, from this specific
branch tip. check_submission.py's own RUBRIC-COMMITS check (`scripts/check_submission.py`
line ~321) uses `git shortlog -sn --no-merges HEAD` WITHOUT merging the two aliased
identities, and reports "min contributor share 7.5%" — even lower than the 22.6% this
audit computes after merging aliases, because it treats T361/Taimoor Shaukat/IfBilal/
8BitNinja as four separate contributors rather than two.

Conclusion: A4 is NOT safely provable either way from a quick check — the true
per-person split depends on which commit set you count (all-refs vs HEAD-reachable
non-merges) and squash-merge attribution quirks. Left UNPROVEN (☐). Whoever finalizes
this row should decide which counting method the marker will actually run
(`git shortlog -sn --no-merges main` against the real `main` branch, post-submission, is
the most likely marker method) and verify the real number against THAT, not against
`--all`.
