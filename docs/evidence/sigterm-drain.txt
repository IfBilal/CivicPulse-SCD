=== Interpretation ===
144 requests that were ALREADY IN FLIGHT when SIGTERM was sent to `backend`: 0 failures.
This proves the app-level graceful-shutdown behavior (backend/app/main.py's
`prestop_drain_s` sleep in the lifespan shutdown hook, plus uvicorn's
`--timeout-graceful-shutdown 25`, backend/Dockerfile:26) works: in-flight requests are
allowed to complete before the process actually exits.

1096 requests that were SENT AFTER the kill signal, while the container was down and
before it restarted: 1070 failed (502/connection errors). This is EXPECTED and NOT a bug —
this compose setup runs exactly one backend replica with no orchestrator to route new
traffic elsewhere while it restarts. This is a materially different scenario from a real
zero-downtime rollout (Kubernetes `maxSurge:1/maxUnavailable:0`, which keeps at least one
healthy replica serving traffic throughout a rollout) — the compose-level SIGTERM-drain
guarantee only covers requests already in progress, not availability during a full
single-instance outage. The Gate 3 checklist's "no 5xx in a concurrent `hey` run" should be
read as testing the drain behavior for in-flight requests specifically, which is confirmed
here; it does not by itself prove zero-downtime deploys, which is a separate, k8s-level
claim (docs/20-RUBRIC-TRACEABILITY.md bonus row "Zero-downtime rollout under live load")
that still needs the k3d/HPA rollout test in docs/handover/HANDOVER-live-infra-evidence.md
§2.8 to be proven for real.
