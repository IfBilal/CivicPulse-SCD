== F · AI layer ==

F1 VERIFIED — backend/app/providers/triage/ has 4 implementations: llm.py, ollama.py,
rules.py, simulated.py (>= 3 required). factory.py selects by `Settings.triage_provider`
(a Literal type, validated by Pydantic).

F2 VERIFIED — llm.py: response content is always parsed via
`TriageResult.model_validate_json(...)` regardless of provider's own "JSON mode" claim;
ValidationError/JSONDecodeError both caught and re-raised as a typed LLMValidationError,
never left to propagate raw past the service boundary.

F3 VERIFIED — triage_service.py has a RETRYABLE tuple (timeouts/connect errors/429/5xx)
separated from a NON_RETRYABLE tuple (ValidationError/malformed-JSON/ValueError). The
retry loop runs at most once (max_retries default 1) inside a shared 12s
(`total_budget_s`) asyncio.timeout deadline, with jittered sleep only on the retryable
branch — non-retryable failures break immediately with zero sleep/retry. Matches
CLAUDE.md HARD rules 5 and 6 exactly.

F4 VERIFIED hashing logic; hit-rate HONESTLY unmeasured — cache.py hashes
NFKC-normalized+casefolded text+location+model via SHA-256. docs/TRIAGE.md explicitly
marks the cache hit-rate as "BLOCKED — needs a real k6 load run against live/CI
infrastructure." No fabricated hit-rate number found anywhere. This means F4's rubric
line ("with a measured, reported hit rate") is NOT met yet — the mechanism is real, the
required measurement is not, and the project is honest about that gap rather than
inventing a number.

F5 VERIFIED — prompt.py documents 5 defence layers (normalise bidi/zero-width chars,
neutralise sentinels, delimit/label untrusted input, constrain output to an enum,
bound blast radius) plus a 6th soft layer in triage_service.py's post-validation.
Tests referencing injection scenarios exist in test_triage_service.py, test_llm.py,
test_simulated.py.

F6 VERIFIED — triage_latency_ms is computed and recorded through triage_service.py and
surfaced via GET /api/meta/providers (routes/meta.py), which returns recent ring
entries including latency_ms.

F7 VERIFIED — docs/adr/0004-pii-and-data-governance.md is 127 lines: a real data
classification table and an explicit "what leaves the machine to a third-party LLM
provider" section citing exact code paths. Not a stub.
